# 交接：批次 3（Sanity 后台）

## 要做什么
1. **账号由灵晞操作**：给出逐步说明。灵晞用 `lixidawn-lab` 相关邮箱注册或登录 Sanity，新建项目 `clinic-site`，dataset 用 `production`，并邀请涵倪为 Editor。Code 不碰任何 token；需要 token 时让灵晞自己填进 Cloudflare 的环境变量和本地 `.env`。
2. **Schema**：和现有 `src/content/` 一一对应，包括 settings（单例）、doctor（单例）、services、faq、howWeBegin、concerns、sources、notes。字段说明用中文写，给涵倪看。
   - 每个字段都分中英文。英文文章只有标题和摘要是必填，正文可以不填（放宽原来的「两种语言都填才能发布」）。
   - notes：`source`、`sourceUrl`、`sourceDate`、`permission`、`needsReview`、`reviewedAt` 照现有规则；`internalNote` 只在后台显示。
   - services 和 faq 带「已确认」开关，没确认的只在预览站显示。
   - 空字段规则不变：预览站显示 TBC，正式站隐藏。
3. **迁移**：写一个一次性脚本，把 `src/content/` 里现有的内容（包括 4 篇文章正文和图片）导入 Sanity。导入后 `src/lib/content.ts` 改为从 Sanity 读取，页面代码尽量不动。保留本地 JSON 作为离线开发的备用。
4. **发布即更新**：Sanity 发布内容时用 webhook 通知 Cloudflare 重新构建（deploy hook）。从发布到网站更新的时间写进回报。
5. **Studio 部署**：用 `sanity deploy` 部署到 `<名称>.sanity.studio`，界面语言用中文（如果有官方中文包就用）。左侧菜单顺序：诊所资料、医生资料、文章、服务、FAQ、如何开始、常见困扰、来源网站。
6. **给涵倪的使用说明**：在 `交接/` 下写一页《后台使用说明》，内容包括：怎么发文章、怎么改营业时间、怎么填 TBC 字段，以及「待审阅」和「转载许可」两个开关是什么意思。不讲技术细节。

## 为什么
涵倪要自己维护所有资料和文章。按 PRD 第 9 节，后台应该在页面完成后接上。

## 怎样算做完
- 在后台改营业时间，几分钟后预览站上就更新。
- 迁移后，`npm run check:production` 照样通过，页面和迁移前一致（截图对比首页和一篇文章）。
- 涵倪能用 Editor 身份登录（先由灵晞测试邀请链接）。
- 写回报、截图、使用说明，更新进度表。
