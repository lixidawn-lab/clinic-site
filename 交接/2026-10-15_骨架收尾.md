# 交接：骨架收尾（流程第 1 步）

## 要做什么
1. 先用 git 提交现有骨架，留一个回退点。
2. 把 `docs/PRD.md`、`docs/checklist.md` 和 `交接/` 纳入仓库，以它们为依据，不再使用暂定文案。
3. TBC 标记的编号和暂定文案按清单编号对齐，并列出改动。
4. 更新 CLAUDE.md 的阶段计划，与 lixi-project-workflow 保持一致：骨架 → 首页设计（灵晞 + Chat，Code 不参与）→ 页面批次 → Sanity → 验收上线。
5. 部署预览：GitHub 仓库连接 Cloudflare Pages，推送后自动部署。注册、登录和授权都由灵晞本人操作，你给出逐步说明，不要碰任何密钥。
6. 确认预览站是 noindex 状态：meta robots 和 robots.txt 都要检查。

## 为什么
骨架之前是在没有需求文档的情况下完成的。首页设计需要在真实链接上评审，而且后面每一批都要依赖预览部署。

## 怎样算做完
- 预览链接可以打开，中英文切换正常，手机宽度下预约栏不遮挡内容。
- 页面源码中有 noindex，robots.txt 为 `Disallow: /`。
- 写回报 `交接/回报_2026-10-15_骨架收尾.md`（一页以内），并附 3–5 张截图，放在 `交接/截图/2026-10-15_骨架收尾/`：手机中文、手机英文、桌面首页、TBC 标记示例。
- 更新 `交接/进度.md`。
- 不做页面视觉设计，那是下一步的事。
